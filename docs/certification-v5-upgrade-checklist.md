# Vandalizer certification upgrade checklist

Bring **every audited dimension and every module’s Vandalizer 5.0 alignment to at least 8/10**. This checklist turns the [October 2 certification audit](reviews/certification-v5-audit.html) into bounded implementation and acceptance work. The target applies to each area independently; a good desktop score cannot compensate for poor mobile behavior, weak grading or unsafe course updates.

**Implementation started October 2, 2026. 133/155 items complete; 22 remain open.** Seven of the original 162 items were removed from scope on October 12, 2026; see [Removed from scope](#removed-from-scope). Track checkpoints, evidence, decisions and resume instructions in the [implementation progress log](certification-v5-implementation-progress.md). Existing functionality can satisfy a verification item when current evidence demonstrates it. Checklist progress does not itself publish a course, migrate learners or raise the audit grades. Keep the original audit as the baseline.

## Completion rules

**Fix** addresses an observed defect. **Improve** specifies a proposed change needed for the target. **Verify** establishes behavior or fills an evidence gap; it does not automatically require new code. **Decide** resolves a course policy needed before implementation. Each item includes its completion condition.

**P0** is the known course-entry failure. **P1** covers task correctness, accessibility blockers, credential integrity and learner protection. **P2** covers the remaining work required for a coherent 8/10 experience. P2 is required for this target, not an optional future wishlist.

Close an item with a source/change reference, relevant automated or observed evidence, and any remaining limitation. Fixture screenshots can close rendering checks; they cannot establish real model behavior, durable persistence, permissions, successful lab execution or learner comprehension. A missing environment or unavailable evaluator remains an open verification item.

## Baselines and acceptance targets

| Dimension | Baseline | Required evidence for at least 8 |
| --- | ---: | --- |
| Chat delivery architecture | 7 | Real start, lessons, lab, assessment, grading, completion and resume work; failures recover and updates remain consistent across surfaces. |
| Desktop visual design | 7 | Clear reading and action hierarchy across all course states, including split views, long content and enlargement. |
| Mobile visual design | 3 | Readable titles and lesson content, reachable actions, usable touch navigation and no clipped controls at narrow and short sizes. |
| Curriculum alignment with 5.0 | 5 | Every module teaches its relevant agentic decisions, includes accurate instructions and assesses the intended outcomes. |
| Assessment validity | 3 | Credit is tied to the learner’s specific evidence and rubric; unrelated artifacts, incorrect results and superficial activity cannot earn competence credit. |
| Safe updates for enrolled learners | 1 | Pinned course versions, durable lesson identity, preserved credit, immutable credentials, tested migration and rollback. |

Module baselines: AI Literacy **5**; Foundations **6**; Thinking in Workflows **4**; Workflow Design **6**; Extraction Engine **5**; Multi-Step Workflows **5**; Advanced Nodes **3**; Output & Delivery **4**; Validation & QA **7**; Batch Processing **5**; Governance **4**. Each must reach **8 or higher**, with no required learning outcome left unassessed.

## Execution order

1. Resolve the entry failure and immediate mobile, feedback and synchronization defects. Preserve a snapshot of the current course before changing assessed requirements.
2. Define the outcome/rubric contract and version model. Build durable enrollment, lesson position and immutable credential support.
3. Update the teaching surfaces, all eleven modules and evidence-based grading together, against a draft course version.
4. Prepare credit mappings, the bridge, administration and migration rehearsals. Keep existing learners on supported requirements during this work.
5. Run the complete evidence matrix, observe representative learners, resolve failures and regrade every area before publication.

Existing document-and-tool composition remains a constraint: preserve the open file, selection, editor and chat context. Reuse existing approvals, source viewers, verification, project and automation tools. This work does not require a new LMS, integrations, public credential directory, parallel certification track or a redesign of unrelated workspace surfaces. Splitting an Agentic Operator course from an advanced Architect course is a later product option, not a condition for this target.
